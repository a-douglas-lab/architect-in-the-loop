## How we work: rules learned the hard way

All are recorded; follow them.

1. **No push before Andy's local review** (ADR-013@v1 C5, C6). Commit locally on a branch, then stop and ask. Andy says when to push and open the PR.
2. **Behaviour is tested before a PR,** with expected results written and committed first (ADR-012@v2 C10). Show a check blocking as well as passing. Model-run checks run three times and are reported as rates. Never edit expected results after a run; add a dated expectation instead.
3. **The adversarial reviewer runs on every documentation change** before Andy sees it: a fresh-context subagent working to [REVIEW.md](../../REVIEW.md), with the diff, the sources and Andy's approvals quoted word for word. Give it raw evidence, not your summary. Record each run on a loop card in [docs/loops/cards/](../loops/cards/).
4. **Every run of a delivery stage gets a loop card** ([docs/loops/README.md](../loops/README.md)), including the leading and lagging indicators.
5. **Challenge, don't assume.** If something isn't recorded as decided in backlog.md, ask Andy, with options and a recommendation. Decisions that contradict each other surface when prose becomes rules, and only a ruling fixes them.
6. **Write constraints clause by clause from the source, and open every file a claim names.** Most of the reviewer's High findings so far came from dropped conditions and unchecked facts, including four factual errors by the author.
7. **Cite constraints with versions:** `ADR-nnn@vN Cn` (ADR-000@v3 C10).
8. **Never access the private evaluation repository** (hard rule 1).

## Item 1: the rule-unit spike

**Problem.** `analyze` reads only the constitution, so a breach buried in ADR text is missed: fixture f8, which breaks ADR-016@v1 C10 (SARIF), was missed in 3 of 3 runs. See backlog T6, "Rule units", for the full proposal.

**Method:** Andy's discernment step (backlog D1):

1. Describe the problem and the criteria.
2. Research prior art, including the same problem solved elsewhere: ESLint and Semgrep rules that ship with tests, `opa test`, adrkit's `affects` and `evaluate`, Claude Code skills and MCP tool search. Bring the findings to Andy **before building anything**.
3. Then build three units of different kinds, each with tests written first:
   - ADR-016@v1 C10, mechanical;
   - ADR-015@v1 C2, judgement;
   - one hard rule.
4. Re-run f8 with its unit loaded, three times, blind. The method is in tests/constitution/README.md. Measure whether the miss becomes a catch.

**Decided:** spike code in Python, in a spike folder. That doesn't decide T5, the capability's stack.

**Done when:** the prior-art write-up has been reviewed by Andy; three units with passing and failing tests exist; f8 has been re-run with a measured result; there's a recommendation on MCP server, skill or pre-`analyze` step; and loop cards and backlog T6 are updated. All local, awaiting Andy's review.
